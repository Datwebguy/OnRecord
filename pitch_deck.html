Who We Are · Core Philosophy

Bridging Autonomous Discovery with Immutable Truth

Modern autonomous agents operate inside transient chat context windows. When sessions close, process IDs die, or context limits trigger compaction, the agent forgets what it did, who it talked to, and what was promised.

OnRecord enforces a hard separation of concerns between investigation and execution: Scout files factual observations into partitioned cold storage, while Clerk independently projects open tasks and verifies prerequisites against storage before any onchain action occurs.

The System Charter
"Scout files only. Clerk acts only on filed tasks. Base pings only execute to a Person with a bound wallet address."
Human-in-the-Loop Safeguard
Agents propose structured actions, but human operators confirm with authenticated cryptographic signatures. Zero runaway background execution loops.

The Challenge

The 3 Critical Flaws in Conventional AI Agents

Why standard language model bots fail enterprise operational audits and cause irreversible onchain errors.

🧠

Ephemeral Amnesia

Standard LLM bots depend on conversational history. When a server reboots or workers restart, context is lost, resulting in repeated tasks, dropped issues, and phantom actions.

🔑

Server Key Exposure

Bots storing BASE_PRIVATE_KEY in environment variables risk wallet draining from malicious prompt injections, leaked debug logs, or unauthorized autonomous calls.

🔄

Runaway Hallucinations

Without an external append-only audit journal, an agent cannot verify if a user is truly registered or if a payment was already dispatched, triggering double-spend cascades.

Sibyl Memory · Cold & Warm Partitions

Sibyl Memory: Partitioned, Local-First, Tamper-Resistant

OnRecord leverages Sibyl Memory client with local SQLite multi-tenant partitioning. Unlike loose vectors or key-value caches, Sibyl separates state into two distinct durability layers:

❄️ COLD Storage: Append-Only Event Journal

Permanent audit trail. Once an event is written (filed, opened, pinged, blocked), it can never be rewritten or modified. Provides complete legal and operational provenance.

🔥 WARM Storage: Materialized Entities & State

Fast key-value access to current state entities (person, ask, task). Enables instant entity verifier lookups without re-parsing raw event streams.

The Proof: The Delete Test Verified Failure Mode

Memory Isolation Invariant

To prove that Clerk does not rely on hidden memory or global variables, our automated test wipes 100% of tenant_scout rows from the database.

1. Wipe Scout memory: DELETE FROM * WHERE tenant = 'scout'
2. Fresh Clerk boots: Queue immediately == 0
3. Entity Check: check_person() -> NOT_ON_RECORD

✓ Zero memory leakage between tenants. Clerk history remains safely isolated.
